# 🌳 00. 思想流派与致敬溯源 (Attributions and Lineage)

**[English](00_attributions_and_origins.md)** | **[简体中文](00_attributions_and_origins.zh.md)**

> *“如果说我看得比别人更远些，那是因为我站在巨人的肩膀上。”* — 艾萨克·牛顿

《Vibe Coding Playbook》（心流编码工程实战手册）并非凭空捏造的一套个人偏好规则。它融合并提炼了经典软件工程数十年沉淀的客观真理，以及当今前沿生成式 AI 与自主 Coding Agent 协同实践的最佳成果。

手册中的每一条核心哲学与行动铁律，均能追溯到经典计算机科学著作、开源软件先驱或国际工业标准。本文档郑重记录并致敬这些智慧源流。

## 📖 核心流派演进深度解读

### 1. Andrej Karpathy 的 AI 编程守则
2024-2025 年间，前 OpenAI 研究科学家 Andrej Karpathy 在使用 LLM 辅助编程时指出了三个常见病灶：
- 大模型极其热衷于在需求不明确时通过“幻觉”自行脑补填空。
- 大模型极喜欢在修复一处小 Bug 时顺带把周围的代码进行“格式化美化”，产生上百行脏 Diff。
- 大模型极其热衷于为了简单的单次需求凭空制造各种泛型、工厂类和过度抽象。
本手册将 Karpathy 的深刻反思制度化、规范化，形成了**支柱 1**。

### 2. John Ousterhout 的深模块哲学
斯坦福大学教授 John Ousterhout 在《软件设计哲学》中揭示：**软件复杂度最大的元凶是浅层封装（Shallow Modules）**。一个类如果仅仅是对另一个库的简单透传，却向调用方暴露了极长的参数列表和底层概念，它就是糟糕的架构。
本手册将其量化为公式并在**支柱 2**中推行：
$$\text{模块深度} = \frac{\text{封装的内部复杂逻辑 (缓存、重试、回退、协议适配)}}{\text{暴露的外部接口复杂度 (参数量、方法数、类型)}}$$

### 3. Matt Pocock 的 Agent 技能工程化范式
Matt Pocock 敏锐地意识到：资深工程师的本能反应（直觉）可以通过结构化的 Markdown 转化为大模型可以 100% 遵守的操作技能。本手册吸收了其在决策前沿逼问、法医式调试、双轨代码审查与工单寻路上的卓越思路，并进一步泛化为适用于多平台的开源标准。

### 4. ASD-STE100 受控语言对大模型 Prompt 的重塑
原本用于保障飞机和武器维护安全的“简化技术英语”（Simplified Technical English），被创新性地引入大模型提示词设计中。事实证明：严禁从句嵌套、严禁分号、单句上限 25 词不仅能让人类一目了然，更能彻底消除大模型的语义漂移，大幅提升推理确定性与缓存命中率。

### 5. 交互状态与动效工程
规则 08 把交互状态与动效工程合并为独立支柱。静态截图无法暴露这一维度。
- **苹果人机界面指南（Motion）** 与 **Material Design** 确立“动效说明空间关系”。共享指示器让用户在切换中保住心理地图。
- **W3C WAI-ARIA 创作实践** 定义互斥展开契约。**尼尔森诺曼集团** 提供单一展开态背后的披露式交互惯例。
- **命令面板谱系**（Sublime Text、VS Code、Linear）证明专家用户选择检索而非逐层导航。**Jakob Nielsen** 的识别优于回忆原则解释了原因。
- **W3C WCAG 2.2**（2.2.2、2.3.3）、**苹果减弱动态效果** 与 **web.dev** 划定可访问性与帧预算的下限。

### 6. 渲染界面验证纪律
规则 09 把「只有渲染之后才存在的东西」如何验证，提炼为一套纪律。
- **Edsger W. Dijkstra** 提供了认识论底线：测试能暴露缺陷，却永远无法证明缺陷不存在。因此「缺少测量」只能判失败，不能判通过。
- **W3C CSS Viewport** 规范与 **Apple 人机界面指南**确立了：没有声明视口、倍率与安全区，布局目标就是空话。
- **平台模拟器与设备工具文档**提供了操作性事实：本地文件协议可能被文件提供者接管；设备标识符、运行时与兼容性会随工具链版本变化。

### 7. 任务拆解与智能体团队分派
规则 10 把分派当作一项有可度量成本的工程决策，而不是能力展示。
- **Fred Brooks** 提供了算术：协调开销的增长快于人数增长，所以向落后的项目加人只会更慢。规则 10.3 把它落成一道显式闸门。
- **Melvin Conway** 提供了结构洞见：系统设计会复刻组织的沟通结构。规则 10.4 把写范围边界做成这条结构可见、可执行的位置。
- **亚马逊 two-pizza team 惯例** 提供了规模启发式：把单元控制得足够小，协调才便宜。规则 10.2 与 10.3 对智能体团队套用同一上限。
- **判官独立与汇总回收纪律**（规则 10.5、10.6）泛化了标准评审实践：作者本人不签字，且没有哪个已分派单元可以无结论悬空。

### 非奠基性灵感来源
