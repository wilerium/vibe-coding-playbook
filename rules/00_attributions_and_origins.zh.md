## 📖 核心流派演进深度解读

### 1. Andrej Karpathy 的 AI 编程守则
2024-2025 年间，前 OpenAI 研究科学家 Andrej Karpathy 在使用 LLM 辅助编程时指出了三个常见病灶：
- 大模型极其热衷于在需求不明确时通过“幻觉”自行脑补填空。
- 大模型极喜欢在修复一处小 Bug 时顺带把周围的代码进行“格式化美化”，产生上百行脏 Diff。
- 大模型极其热衷于为了简单的单次需求凭空制造各种泛型、工厂类和过度抽象。
本手册将 Karpathy 的深刻反思制度化、规范化，形成了**支柱 1**。

### 2. John Ousterhout 的深模块哲学
斯坦福大学教授 John Ousterhout 在《软件设计哲学》中揭示：**软件复杂度最大的元凶是浅层封装（Shallow Modules）**。一个类如果仅仅是对另一个库的简单透传，却向调用方暴露了极长的参数列表和底层概念，它就是糟糕的架构。
本手册将其量化为公式并在**支柱 2**中推行：
$$\text{模块深度} = \frac{\text{封装的内部复杂逻辑 (缓存、重试、回退、协议适配)}}{\text{暴露的外部接口复杂度 (参数量、方法数、类型)}}$$

### 3. Matt Pocock 的 Agent 技能工程化范式
Matt Pocock 敏锐地意识到：资深工程师的本能反应（直觉）可以通过结构化的 Markdown 转化为大模型可以 100% 遵守的操作技能。本手册吸收了其在决策前沿逼问、法医式调试、双轨代码审查与工单寻路上的卓越思路，并进一步泛化为适用于多平台的开源标准。

### 4. ASD-STE100 受控语言对大模型 Prompt 的重塑
原本用于保障飞机和武器维护安全的“简化技术英语”（Simplified Technical English），被创新性地引入大模型提示词设计中。事实证明：严禁从句嵌套、严禁分号、单句上限 25 词不仅能让人类一目了然，更能彻底消除大模型的语义漂移，大幅提升推理确定性与缓存命中率。
