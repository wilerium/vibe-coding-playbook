# 🎞️ 08. 交互状态与动效工程 (Interaction State & Motion Engineering)

**[English](08_interaction_and_motion.md)** | **[简体中文](08_interaction_and_motion.zh.md)**

> *“动画不是让画动起来，而是把动作画出来。”* — 诺曼·麦克拉伦 (Norman McLaren)

---

## 🎯 核心问题：“跳切式界面”陷阱

规则 04 管信息密度与视觉质感。规则 08 管时间维度。一张静态截图可以完全正确，用起来依然别扭。

1. **状态硬切**：点击后内容先消失再出现。用户丢失空间位置感。
2. **动效参数拍脑袋**：AI 要么不做动效，要么给出 500ms 弹跳。每次交互的节奏互不相干。
3. **多组同时展开**：多个导航组一起展开。注意力被摊薄，布局跟着跳动。
4. **状态藏在详情页**：未读、失败、待办必须逐行点开才看得见。
5. **导航吃掉画布**：常驻侧栏为 6 个链接占掉 20% 可用宽度。
6. **动效没有约束**：无限动画一直转；热路径上动画布局属性；没人处理 `prefers-reduced-motion`。

## 📜 规则 8.1：状态位移化，不要硬切 (Continuity Over Cut)
*(思想溯源：苹果人机界面指南 Motion 章节 & Material Design 动效规范)*

**核心铁律**：把状态变化表达成几何位移，而不是“消失 + 出现”。

### 三种成熟手法

1. **共享指示器（浮动高亮块）**：
   - 整组导航共用一块圆角高亮元素。
   - 选中项变化时，高亮块从旧位置移动到新位置。
   - 高亮块宽度跟随目标文字宽度。
2. **错落入场（级联）**：
   - 子项从父项边缘逐条进入。
   - 每一项比前一项延迟 20ms 至 30ms。
   - 整段级联在 400ms 内结束。
3. **数字滚动**：
   - 变化的数字向上离开，新数字从下方进入。
   - 只移动数字列。容器尺寸不变。

```css
.nav { position: relative; }

/* 整组共用一个绝对定位指示器。 */
.nav__indicator {
  position: absolute;
  top: var(--y, 0);
  left: 0;
  height: var(--h, 36px);
  width: var(--w, 0);
  border-radius: 10px;
  background: var(--accent-soft);
  transition: transform 200ms cubic-bezier(0.2, 0, 0, 1),
              width 200ms cubic-bezier(0.2, 0, 0, 1);
}

/* 级联：为每个子项设置 --i。 */
.subitem {
  opacity: 0;
  transform: translateY(-4px);
  transition: opacity 180ms ease-out,
              transform 180ms ease-out;
  transition-delay: calc(var(--i, 0) * 24ms);
}
[data-open="true"] .subitem { opacity: 1; transform: none; }
```

**反例（不该用时）**：
- 位移距离超过一屏。改用瞬时切换并配合滚动锚点。
- 列表做了虚拟滚动。程序化滚动时禁用过渡，无动画地移动指示器。
- 用户正在拖拽或滑动。绝不对用户直接控制的值做动画。

## 📜 规则 8.2：单一展开态不变量 (The Single-Expansion Invariant)
*(思想溯源：WAI-ARIA 创作实践 Accordion 模式 & 尼尔森诺曼集团披露式交互惯例)*

**核心铁律**：同一个层级里，只允许一组处于展开或激活状态。

### 状态机

```text
空闲 -> 收起(上一组) -> 展开(目标组) -> 空闲
```

1. 先收起上一组，再展开目标组。
2. 需要两段重叠时，第二段延后 60ms。绝不在同一帧启动两段。
3. 用 `aria-expanded` 播报状态。切换控件必须可用键盘到达。
4. 高度用 `grid-template-rows` 或实测高度做动画。不要猜一个 `max-height`。

```css
.panel {
  display: grid;
  grid-template-rows: 0fr;
  transition: grid-template-rows 220ms cubic-bezier(0.2, 0, 0, 1);
}
.panel[data-open="true"] { grid-template-rows: 1fr; }
.panel > .panel__inner { overflow: hidden; }
```

**反例（不该用时）**：
- 用户需要并排对比两组内容。改用多列布局。
- 界面是文件树。那里多组同开是语义要求。
- 选中态需要跨父组保留。显式建模这个状态，别塞进手风琴。

## 📜 规则 8.3：状态外置 (State Externalization)
*(思想溯源：苹果人机界面指南 Badges 章节 & W3C WCAG 2.2)*

**核心铁律**：把新、未读、异常状态标在导航行上。不要逼用户钻取。

### 三档标记

| 档位 | 标记 | 适用 |
| :--- | :--- | :--- |
| 存在性 | 6px 圆点 | 有内容，数量未知 |
| 数量级 | 数字徽标 | 数量本身影响决断 |
| 严重度 | 彩色圆点或描边 | 该项需要紧急处理 |

1. 大数截断为 `999+`。把精确值放进无障碍名称与悬浮提示。
2. 数字变化用垂直滚动。不要动画徽标尺寸。
3. 用户访问目标后清除徽标。用 150ms 缩放到 0。
4. 绝不只用颜色表意。颜色必须搭配形状、图标或文字。
5. 用礼貌级实时区域播报数量变化。不要打断用户。

```css
.badge--breathing {
  animation: breathe 1800ms ease-in-out infinite;
}
@keyframes breathe {
  0%, 100% { opacity: 0.65; transform: scale(0.96); }
  50%      { opacity: 1;    transform: scale(1.04); }
}
```

**反例（不该用时）**：
- 数量本身就是核心业务指标。放到仪表盘。徽标会掩盖量级。
- 每一项都挂徽标。长期告警等于噪音。去修流程，别修徽标。

## 📜 规则 8.4：导航占位预算 (The Navigation Pixel Budget)
*(思想溯源：尼尔森诺曼集团信息架构 & 规则 00 所列菜单形态调研)*

**核心铁律**：把导航占用的空间当作显式预算。形态决定可用画布，也决定可达层级深度。

| 形态 | 占用 | 适用 | 失效场景 |
| :--- | :--- | :--- | :--- |
| 常驻侧栏 | 200px 至 280px 宽 | 8 至 20 项，2 至 3 层，指针输入 | 内容需要全宽，或屏幕偏窄 |
| 顶栏 + 巨型面板 | 全宽，约 48px 高 | 5 至 9 个主项，宽详情面板 | 层级超过 3 层，或仅触屏输入 |
| 底部浮动停靠栏 | 占据内容角落，约 64px 高 | 最多 7 个纯图标入口 | 必须靠文字才能理解功能 |
| 仅命令面板 | 零常驻占用 | 专家工具，键盘重度用户 | 靠识别浏览的新手 |
| 混合（侧栏 + 面板） | 侧栏加一个热键 | 用户结构复杂的大型产品 | 两套入口逐渐失同步 |

1. 低于 200px 时，常驻侧栏的代价大于收益。折叠成图标。
2. 触屏为主的产品绝不做悬停展开的导航面板。触摸没有悬停态。
3. 首屏必须可见主导航。隐藏菜单要有可见的搜索兜底。

**反例（不该用时）**：
- 自助终端或单任务视图。直接去掉导航，只留一个出口。
- 营销页面。导航占位服务叙事，不套用工具类预算。

## 📜 规则 8.5：检索优先于层级 (Retrieval Over Hierarchy)
*(思想溯源：命令面板谱系（Sublime Text、VS Code、Linear）& 尼尔森“识别优于回忆”)*

**核心铁律**：可导航目标超过约 20 个时，提供直接检索。不要再加深层级。

### 性能预算

| 阶段 | 预算 |
| :--- | :--- |
| 热键后唤起面板 | 150ms 以内 |
| 每次按键后过滤 | 100ms 以内，本地同步完成 |
| 高亮命中子串 | 与过滤结果同一帧 |

1. 支持 `上`、`下`、`回车`、`Esc`。鼠标可选，绝不能是必需。
2. 压暗并模糊背景。面板自身对比度保持 WCAG AA 以上。
3. 精确前缀匹配排在模糊匹配之前。在结果行里显示排序依据。
4. 命令列表保持确定性。同一查询必须给出同一顺序。

**反例（不该用时）**：
- 用户不知道目标叫什么。此时浏览强于搜索。保留视觉导航的一等地位。
- 条目少且稳定。命令面板只增加一个模式，没有收益。
- 产品以触屏为主。命令面板是专家捷径，不能是唯一路径。

## 📜 规则 8.6：动效可访问性与性能红线 (Motion Accessibility & Performance Red Lines)
*(思想溯源：W3C WCAG 2.2（2.2.2、2.3.3）、苹果“减弱动态效果”、web.dev 渲染性能)*

**核心铁律**：动效必须可选、可打断、开销低。可访问性与帧预算属于发版阻断项。

1. **尊重减弱动态效果偏好**。把位移换成透明度或颜色变化。状态反馈必须保留。
2. **热路径只动画 `transform` 与 `opacity`**。列表或滚动容器里绝不动画 `top`、`left`、`width`、`height`。
3. **反馈要快**。直接操控反馈必须在 150ms 内启动。单段动效总时长控制在 400ms 以内。
4. **禁止无动机的无限动画**。徽标轻微呼吸可以。常驻旋转的装饰不行。
5. **绝不把焦点可见性动画掉**。焦点环瞬时出现并保持可见。
6. **尊重用户打断**。新输入立即取消进行中的过渡。绝不排队动画。
7. **长列表要做包含**。加 `contain: layout paint`，让单行动画不刷新整页。

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
  /* 保留反馈：把位移换成透明度。 */
  .subitem { transform: none !important; }
}
```

## 📊 动效参数速查表

| 交互 | 时长 | 缓动 | 备注 |
| :--- | :--- | :--- | :--- |
| 悬停、按下、聚焦反馈 | 120 - 160ms | `cubic-bezier(0.2, 0, 0, 1)` | 必须 150ms 内启动 |
| 共享指示器位移 | 180 - 240ms | `cubic-bezier(0.2, 0, 0, 1)` | 仅选中态可加轻微过冲 |
| 指示器宽度变化 | 180 - 240ms | `cubic-bezier(0.2, 0, 0, 1)` | 与位移保持同相 |
| 展开与收起高度 | 200 - 260ms | `cubic-bezier(0.2, 0, 0, 1)` | 收起比展开快约 20% |
| 子项级联单项 | 160 - 200ms | `ease-out` | 每项延迟 20 - 30ms，总计 400ms 内 |
| 数字滚动 | 180 - 240ms | `ease-out` | 容器裁剪，绝不改变尺寸 |
| 徽标出现 | 150ms | `ease-out` | 从 0.8 缩放到 1 |
| 徽标消除 | 120ms | `ease-in` | 缩到 0 后从节点树移除 |
| 呼吸提醒 | 1600 - 2000ms 循环 | `ease-in-out` | 幅度不超过 8% |
| 命令面板唤起 | 120 - 150ms | `cubic-bezier(0.2, 0, 0, 1)` | 遮罩与面板同相进入 |
| 页面级转场 | 240 - 320ms | `cubic-bezier(0.2, 0, 0, 1)` | 仅层级跳转使用，同级切换不用 |

**三条锚点**：反馈要快（150ms 以内）。空间转换适中（300ms 以内）。任何动效不超过 400ms。

## 🤖 给 AI Agent 的提示词模板

用这些模板替代随口描述。替换方括号字段，保留约束句。约束句用来阻止模型自行发明动效参数。

```text
[1] 滑动高亮导航
组件：[名称]。项数：[数量]。输入方式：[指针 | 触摸 | 键盘]。
增加一个圆角高亮元素，服务整组。
选中项变化时，高亮块从旧位置移动到新位置。
宽度跟随目标文字宽度。时长 200ms，缓动 cubic-bezier(0.2,0,0,1)。
只动画 transform 与 opacity。遵守 prefers-reduced-motion。

[2] 就地展开，单一展开态
组件：[名称]。层级：[深度]。每层项数：[数量]。
子项在父项下方就地展开。
箭头旋转 90 度。子项按每项 24ms 延迟级联入场。
前缘画一条 1px 竖向连接线。
每层只允许一组展开。先收起上一组。
用 aria-expanded 播报状态。高度用 grid-template-rows 做动画。

[3] 导航行状态外置
组件：[名称]。档位：[圆点 | 计数 | 严重度颜色]。
在每行导航右侧渲染状态标记。
存在性用 6px 圆点，数量用数字徽标，严重度用彩色描边。
计数截断为 999+，并向辅助技术暴露精确值。
数字变化时垂直滚动 200ms。访问后 150ms 内清除标记。
绝不只用颜色表意。

[4] 导航形态改造
组件：[名称]。当前形态：[侧栏]。目标形态：[顶栏 + 巨型面板]。
把主导航移到[目标形态]。把回收的宽度还给内容区。
悬停时下落一整块通栏面板。子页面按列排布，每项带图标和一行说明。
指针在项间移动时面板保持打开，只切换内容。
触屏为主的产品绝不依赖悬停。

[5] 命令面板
组件：[名称]。命令数：[数量]。
增加由[热键]唤起的命令面板。
在屏幕中央弹出。压暗并模糊背景。
每次按键都在本地同步过滤。高亮命中子串。
支持 上、下、回车、Esc。唤起耗时 150ms 以内。
同一查询的命令顺序保持确定性。
```

## 🚨 交互与动效核对清单

- [ ] 每处状态变化是否读作位移，而不是跳切？
- [ ] 每个层级是否只保留一组展开？
- [ ] 新、未读、异常状态是否直接标在导航行上？
- [ ] 导航占位是否经过显式决策，而非沿用默认？
- [ ] 可导航目标超过约 20 个时，是否提供直接检索？
- [ ] 每处动效是否遵守 `prefers-reduced-motion: reduce`？
- [ ] 热路径是否只动画 `transform` 与 `opacity`？
- [ ] 直接操控反馈是否 150ms 内启动、400ms 内结束？
- [ ] 每个状态是否不依赖颜色也能读懂，不依赖鼠标也能到达？
- [ ] 焦点指示器是否瞬时、可见、且从未被动画掉？
