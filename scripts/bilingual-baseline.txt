# 双语结构基线（已知欠账登记）

> **这个文件存在的唯一目的：让豁免可见，而不是让检查静默放行。**
>
> CI 的 `bilingual` 检查要求每个 `*.zh.md` 与对应 `*.md` 的结构指标相等。
> 仓库里存在**本规则生效之前就有的**历史不一致。若让 CI 直接全红，它会立刻变成
> 「狼来了」——没人会认真看一个恒定失败的红叉，最终整道闸门被绕过。
>
> 所以：**现有不一致登记在此，CI 只拦「新增」不一致。** 这里每一条都是待还的债，
> 不是许可。修平后请从本文件删除对应行；**不得**为了让 CI 变绿而往里加行。

## 结构指标定义

| 指标 | 含义 |
| :--- | :--- |
| `lines` | 文件总行数 |
| `h2` | `^## ` 开头的二级标题数 |
| `rules` | `^## 📜` 开头的规则条款数 |
| `tables` | `^| :---` 开头的表格分隔行数 |
| `checklist` | `^- [ ]` 开头的核对项数 |

## 关于 06 这条

`06_governance_and_reviews.zh.md` 的不一致不是排版差异，是**条款编号重复**：

- 中文侧「规则 6.5」出现两次，分别讲「文档双语同步」与「提交门禁（直推 vs 必须开 PR）」
- 英文侧只有「Rule 6.5: Documentation Twin Synchronization」

成因：`dfc35c4` 补全中文文档时，`5ae9dbd` 又把「提交门禁」以 6.5 编号加进了中文侧，两边没有对齐。

**修法需要重新编号（6.5→6.6 或其它），属于跨仓库约定变更**（规则编号被上层工作区准则与团队角色卡引用），应单独提 PR 处理，不宜夹在基础设施 PR 里。

## 维护规则

1. **只减不增。** 新增条目必须是「本轮基础设施之前就存在」的欠账，并在 PR 里说明为何不能当场修。
2. **修平即删行。** 指标对齐后立刻删除对应行，不留过期豁免。
3. **单行即失效。** 若某文件的实际指标与登记值不再匹配（无论变好还是变坏），CI 报错——防止用过期基线蒙混。
